# Robot Learning Lab — Goal-conditioned Offline RL

A reproducible, interactive **state-based simulation study** comparing GCBC, GCIQL and HIQL on OGBench Cube Single / Double. This project adds an experiment harness, traceable evaluations, ablations and a browser replay explorer around pinned upstream algorithm implementations.

[Open interactive replay](https://raw.githack.com/Fjj040806/Offline-Reinforcement-Learning-for-Robotic-Manipulation/main/ogbench/docs/index.html) · [Results and limitations](docs/REPORT.md) · [Mathematical objectives](docs/METHODS.md) · [Machine-readable evidence](docs/results.json) · [Resume bullets](docs/RESUME.md)

The browser page is a self-contained HTML file. It can also be downloaded and opened locally. It visualizes recorded states; it does not run a live robot policy or MuJoCo in JavaScript.

## What is included

- Pinned upstream GCBC, GCIQL and HIQL implementations and original license.
- Two real datasets, 3 training seeds per method, fixed evaluation starts and checkpoint rules.
- Per-episode success/failure, learning curves, trained Flax inference weights and sampled state trajectories.
- Dataset-size and HIQL subgoal-interval ablation runners.
- Interactive environment / algorithm / seed / task selection, playback, scrubbing and camera rotation.
- Tests checking experiment completeness and consistency with displayed results.

**This is a small CPU-budget experiment, not a reproduction of the published performance table or evidence of real-world deployment.** Inspect the report for measured results, including failures. GCBC is imitation learning; GCIQL and HIQL are the RL methods.

## Install

Tested with Python 3.12 on Linux, CPU JAX. Use an isolated environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Full environment inventory: `requirements-lock.txt`. It also contains unrelated packages from the execution environment; the focused requirements file is the installation entry point. To use a GPU install an appropriate JAX accelerator build for your hardware.

## Reproduce the core study

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MUJOCO_GL=egl \
XLA_FLAGS=--xla_cpu_multi_thread_eigen=false python scripts/suite.py --retrain
python scripts/export_weights.py
python scripts/aggregate.py
python scripts/build_demo.py
python -m unittest discover -s tests
```

`suite.py` uses Linux `taskset` and up to three workers, adapting worker count to the visible CPU count. For smaller machines, run the individual command below instead. Windows users should use WSL; the runner uses Unix output-directory locks. Data are cached in `ogbench/data/` and checked against recorded SHA256 values. Data download uses the official OGBench host; approximately 581 MiB on disk for four files, plus expanded arrays in memory. Set `--data-dir` explicitly when running on a different layout.

## Individual training / evaluation

```bash
python scripts/run.py --algorithm gciql --dataset cube-single-play-v0 \
  --seed 0 --steps 20000 --episodes 50 --width 128 --batch 256
```

To reproduce evaluation without retraining, add `--restore` with the same architecture and `--out` pointing to its experiment directory. Inference weights use Flax msgpack, not Python pickles. Optimizer states are omitted from GitHub to reduce download size; `--restore` loads weights for evaluation, not continuation of an interrupted training optimizer.

To train a larger-budget model, specify `--steps 1000000 --width 512 --batch 1024 --out experiments/long-budget`. This CLI still uses two hidden layers; an exact upstream 512×512×512 reproduction should use the original `vendor/impls/main.py` and published configuration. Published benchmark defaults are not claimed here.

## Ablations

```bash
MUJOCO_GL=egl OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 \
XLA_FLAGS=--xla_cpu_multi_thread_eigen=false python scripts/ablations.py --retrain
```

Ablation inference weights are regenerated by training; core inference weights are committed. Ablations use 10 development reset seeds per task (20000–20009), disjoint from core evaluation. Dataset fractions select entire trajectories with fixed subset seed 42, shared between methods. Complete-data / interval-10 checkpoints are reused and reevaluated on development starts.
